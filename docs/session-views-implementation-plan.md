# 会话视图与项目归属实施计划

## 目标与范围

为用户提供两种可切换、可记住的会话列表视图：按项目分组和按最近活动时间排列。两种视图均清楚显示项目归属，项目外的普通会话标记为“独立会话”。切换只改变呈现方式，不修改会话数据、Pi 历史、项目路径、worktree 或工作目录。

本期不实现会话迁移、手动重新关联项目、跨设备设置同步或导入外部 Pi 会话；这些功能需要单独设计，因为改变归属可能影响后续读写目录。

## 现状

- `PiAgentSessionRecord` 已持久化 `projectPath`、`projectName`、仓库和可选 `worktreePath`。普通项目会话的空 `projectPath` 表示无项目；Agent Deck Builder 是其中需要单独识别的特殊模式。
- `PiAgentSessionStore` 分别创建项目会话、普通无项目会话和 Builder 会话。项目会话的工作目录优先使用 worktree，否则使用项目路径；无项目会话使用专属工作目录。
- 展开面板的 `computedSections` 对当前/关注会话按项目分组，但把其他会话放入按时间排列的 `Previous Sessions`；后者按页显示，并允许批量删除全部匹配的历史会话，包括未展开的项目。
- `PiAgentSessionGrouping` 已支持项目、无项目、Builder、未解析路径及项目扫描尚未完成时的暂存分组。折叠面板有独立列表计算，不能假定其与展开面板相同。
- `AppSettings`、`AppSettingsController`、`AppViewModel` 和 `SettingsSceneContent` 已有设置持久化和绑定模式，可沿用；`PiAgentSessionGroupingTests` 已覆盖部分分组、筛选和分页行为。

## 产品行为

### 1. 视图选择与默认值

- 在展开的会话列表标题附近增加可访问的视图菜单：**按项目**、**按最近活动**；在现有设置界面提供相同选项，两处修改同一持久化设置，并立即生效。
- 建议默认“按最近活动”，保持老用户对历史列表的时间排序预期；新旧用户使用相同默认值，设置不存在或值未知时安全回退。该默认值实施前可调整。
- 切换和重启后保留所选模式；每个模式的项目折叠状态和列表展开状态互不干扰。保留当前选中会话和输入草稿，不启动、停止或重建会话。

### 2. 按项目视图

- 全部匹配会话，包括历史会话，都归入所属项目组；组内按最近活动排序，保留置顶、工作中和待处理状态的现有可见性规则。显示每组总数，允许折叠及按需加载更多。
- 无项目普通会话归入“独立会话”；Agent Deck Builder 保持独立类别，不混入普通独立会话。
- 已记录项目路径但扫描完成后无法匹配的会话放入“项目未找到”，展示保存的项目名称及路径，并保留原归属；扫描尚未结束时显示“项目扫描中”或基于已保存信息的临时分组，避免误报。未被发现不必然代表文件已删除。
- 相同项目名称但路径不同的项目必须分开；有同名歧义时展示路径或仓库信息。worktree 会话仍按原项目路径归组，可附带分支标识。

### 3. 按最近活动视图

- 按现有近期/置顶和历史列表规则排列，保留现有分页与“显示更多”能力；每一行都显示项目名称、独立会话、Builder 或项目未找到的清晰标签。
- 同名项目通过路径或仓库辅助区分；显示标签不改变数据归属。切换模式不复制或丢失任何会话。

### 4. 共同交互

- 搜索、待处理筛选、多选、置顶、删除、键盘导航和当前运行状态在两种视图中保持有效。搜索至少覆盖会话标题和项目名称；检查现有匹配规则，按需补充路径匹配，并避免分页隐藏搜索结果。
- 历史批量删除的范围必须保持明确：确认框展示实际数量，且说明是否包括折叠或分页隐藏的会话；按项目视图不得把原“删除全部历史”的行为误导为只删除当前项目。项目删除入口若要引入，须单独明确范围，本期优先保留现有安全语义。
- 仅对实际可见行进行键盘导航；过滤或切换造成当前会话不在可见列表时，不删除也不切换实际选中会话，提供可见提示或清晰恢复路径。切换模式、折叠和搜索时避开活动会话的列表顺序冻结，确保结构变化立即生效。
- 可访问性名称需包含会话名称及归属；分组按钮提供展开状态。紧凑/折叠面板维持既有布局，但其会话归属仍可通过可访问名称或提示查看；展开面板是视图切换的主要范围。

## 实施步骤

1. **设置模型**：在 `AppSettings` 定义稳定的视图模式枚举和默认回退；沿用 `AppSettingsController` 与 `AppViewModel` 的持久化链路，确保旧设置文件及未知值可加载。添加设置项与列表标题切换入口。
2. **统一归属判断**：在会话分组层构建可测试的展示分类：项目、独立、Builder、扫描中及未找到；复用已存路径和名称，保留特殊会话类型。按项目路径标识分组，不通过名称或目录包含关系推断归属。
3. **构建两套展示数据**：扩展 `PiAgentSessionGrouping` 和 `PiAgentViews`，按选定模式计算分区、分页、置顶和活动状态；确保所有会话恰好出现一次，扫描状态变化可刷新分组，同时保留展开/折叠、当前选择、排序冻结和可见导航的既有优化。
4. **添加行标签与交互**：在 `PiAgentSessionListViews` 相关行中展示归属及同名消歧信息；检查搜索、删除确认、辅助功能和紧凑视图。不要因为视图变化改写 session、worktree 或项目文件。
5. **文档与验证**：更新用户可见的会话管理说明，记录两种模式、独立会话和项目未找到的含义；按下列矩阵运行测试与人工验收。

## 测试与验收

- **分组与兼容**：多个项目、同名不同路径、独立会话、Builder、worktree、历史会话、空数据；每个会话只出现一次且不跨项目。旧设置无字段、未知枚举值可回退；旧会话无需改写即可展示。
- **发现状态**：项目扫描中、扫描完成找不到、重新发现、项目移动后旧路径未匹配；不把未知或已失联项目标为独立会话。
- **交互**：两种模式切换、重启持久化、搜索项目名称、筛选、置顶、分页、折叠、多选、键盘导航和删除确认；核对隐藏项及批量删除实际数量。
- **运行与性能**：切换时会话流式输出和输入法组合输入不中断；活动项目状态更新后标签和排序正确；大量会话下检查列表展开与切换流畅性。确认无会话记录、Pi 历史文件、项目路径或工作目录因切换被修改。
- **执行**：先运行 `PiAgentSessionGroupingTests` 及相关设置和列表测试，再按项目指南运行 Debug 构建和完整测试；用真实 macOS 界面人工检查两种视图及 VoiceOver 标识。记录不能运行的测试和原因。

## 验收结果

用户可以随时在两种视图间切换并在重启后保留选择；任何会话都能看出项目归属或独立状态，历史会话也不例外；项目无法识别时不会误标为独立会话。模式切换不改变会话实际运行环境，也不损坏原有操作。
